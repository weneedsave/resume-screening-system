# AI 简历筛选系统

一个用来筛简历的小工具，Flask 写的，带个网页界面。把一堆简历丢进去，它帮你把里面的人名、电话、学历这些东西抽出来，再根据你写的岗位要求打个分，排个序，省得一份份翻。

## 它能干什么

简历支持 pdf、docx 和图片三种，可以一次传好几份。传上去之后系统会把文本解析出来，按字段整理好存进数据库。pdf 和 word 是直接读文字的，图片简历会先让大模型看一遍，不行再走本地 OCR。

然后你新建一个岗位，把学历要求、工作年限、必须会的技能、加分技能这些填上。点开始筛选，它就拿每份简历跟岗位比，算出个分数，从高到低排出来，还告诉你缺了哪些硬性技能。

打分是规则算的，学历占一部分，专业占一部分，技能、年限、关键词各占一部分，缺必须技能会扣分。最后还会让大模型再扫一眼，给句建议，但大模型只是参考，不直接决定分数。

## 怎么跑起来

先装依赖，项目根目录有个 requirements.txt，pip 装上就行。Python 版本要 3.11 以上。

然后是配置。项目里的 .env.example 是一份模板，复制一份改名成 .env，把里面 DASHSCOPE_API_KEY 换成你自己的。这个 key 是阿里云百炼的，不填的话图片解析和 AI 辅助分析用不了，但纯 pdf 和 word 的规则打分还是能跑的。

如果要用本地 OCR 兜底，还得装个 Tesseract，把 TESSERACT_EXE 和 TESSDATA_DIR 在 .env 里指到你的安装路径。

这些都弄好了，直接运行 app.py，浏览器打开 127.0.0.1:5000 就能看到界面了。

调试模式默认是**关闭**的。本地开发想要热重载和详细报错页，设置环境变量再启动：

```bash
FLASK_DEBUG=1 python app.py        # Linux / macOS / Git Bash
set FLASK_DEBUG=1 && python app.py # Windows CMD
```

## 数据存哪

用的 SQLite，跑起来会自动生成一个 resume_ai.db。简历、岗位、匹配结果都在里面，删掉这个文件就是清空数据。数据库和上传的简历文件都不会提交到仓库，本地自己用就行。

## 评分怎么算

总分 100，五个维度加权，再对缺失的硬性技能扣分：

| 维度 | 满分 | 说明 |
|---|---|---|
| 学历 | 20 | 按学历等级比较（大专 3 / 本科 4 / 硕士 5 / 博士 6 / 博士后 7） |
| 专业 | 15 | 岗位设置的专业关键词命中即给分 |
| 技能 | 35 | 必须技能 28 + 加分技能 7（每个 1.5 分，上限 7） |
| 工作年限 | 20 | 从简历全文用正则提取，满足给满分，不足按比例 |
| 关键词 | 10 | 每个命中 2 分，上限 10 |
| **扣分** | -30 | 每缺一个「必须技能」扣 8 分，上限 30 分 |

**大模型不参与算分。** 它只在最后追加一段参考建议（`ai_review`），规则评分完全可解释、可复现。

## 已知局限

这些是当前实现里明确知道的问题，写在这里而不是假装不存在：

- **技能匹配依赖词边界，会牺牲一点召回。** 要求「go」不会再误命中简历里的「django」「google」（修复前会），代价是「golang」也不再算命中；中文技能按子串匹配，没有这个问题。
- **工作年限从全文用正则抠，做不到 100% 准。** 已经排除了「2022年入学」这类年份数字，但如果写法特殊（年限写在表格里、用「三年」这种中文数字），仍会漏。
- **岗位未设置某维度时给的是"中性分"**（学历 10 / 专业 8 / 年限 10）。语义是"该维度不构成区分度"，副作用是岗位什么都不填时仍有 28 分基准分。
- **批量筛选是同步串行的。** `/api/jobs/<id>/match` 会遍历所有简历，每份同步调一次大模型；100 份简历就是 100 次串行调用，会把 HTTP 请求挂住。正确做法是把 AI 建议拆成异步任务，先返回规则排名——规则打分本身是毫秒级的。
- **列表接口没有分页**，`SELECT *` 会把简历全文一起读进内存。
- **OCR 效果依赖扫描件质量**，`--psm` 取值是试出来的经验值，复杂排版不一定有效。
